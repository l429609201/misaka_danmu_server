## 弹幕库 · 条目结构与列表

> 别名: 媒体库, 弹幕库页面, 条目, 作品列表, 番剧列表, 影视列表

「弹幕库」页面集中管理所有已导入的作品条目，是本服务的核心页面。

**条目的三层结构**（回答用户时务必用这套术语）：

```
条目（作品）——一部电影或剧集
├── 基础信息：标题、年份、类型、海报
├── 别名列表：用于提高播放器匹配成功率
├── 弹幕来源 1（如"腾讯"）
│   ├── 分集 1（含集数、标题、弹幕数量）
│   └── 分集 2
└── 弹幕来源 2（如"B站"）
    └── 分集 1
```

**列表页能做什么**：
- 按标题搜索条目
- 按类型筛选（电影 / 剧集）
- 查看每个条目的海报、标题、来源数量、分集数量
- 批量操作（多选后统一处理）

## 弹幕库 · 编辑条目信息

> 别名: 修改标题, 改名, 加别名, 编辑元信息, TMDB ID, 年份, 季度, 类型

点击条目进入详情页后可编辑：

| 字段 | 说明 |
|---|---|
| 标题 | 作品主标题 |
| 别名 | 可加多个，**播放器匹配不上时优先加别名** |
| 年份 | 上映/播出年份 |
| 类型 | 电影 或 剧集 |
| TMDB ID / TVDB ID | 关联的元数据 ID，用于刮削 |

**别名的作用**：播放器请求弹幕时用文件名去匹配，别名越全命中率越高。
可通过定时任务「TMDB自动刮削与剧集组映射」自动补充别名。

## 弹幕库 · 删除条目

> 别名: 删除作品, 删掉番剧, 移除条目, 清除

在条目详情页或列表页可删除条目。

⚠️ **删除条目会连带删除其下所有弹幕来源和所有分集的弹幕数据，不可恢复。**
建议删除前先用「数据库备份」功能做备份。

## 弹幕库 · 弹幕来源管理与默认来源

> 别名: 数据源, 源列表, 切换源, 默认源, 默认来源, 优先源, 哪个源生效, 来源管理

一个条目可关联多个弹幕来源（B站、爱奇艺、优酷、腾讯、芒果等）。

**在条目详情页可看到**：来源名称与图标、该来源下的分集数量、来源状态。

**切换默认来源**：当一个条目有多个来源时，可指定默认来源。
**播放器请求弹幕时，会优先返回默认来源的弹幕。** 这是决定"实际用哪个源的弹幕"的开关。

典型用法：哪个源弹幕多/质量好，就把它设为默认来源。

## 弹幕库 · 分集管理（刷新与删除分集）

> 别名: 分集列表, 集数, 刷新弹幕, 重新抓取, 删除分集, 弹幕数量

点击某个弹幕来源可进入分集列表，每集显示：分集编号、分集标题、弹幕数量、最后更新时间。

**刷新分集弹幕**：手动从源站重新抓取该集最新弹幕。
适用于：源站弹幕又涨了、之前抓取不完整、弹幕有误。

**删除分集**：删除该分集及其弹幕数据。

## 弹幕库 · 自定义创建条目

> 别名: 新建条目, 手动创建, 手动添加作品, 自建条目

不从弹幕源搜索，直接手动创建一个条目。

**步骤**：
1. 「弹幕库」页面点击 **新建条目**
2. 填写：标题（必填）、类型（电影/剧集）、年份、别名
3. 点击 **创建**

**适用场景**：
- 要导入本地已有的 XML 弹幕文件（需先有个条目挂载）
- 该作品在所有弹幕源里都搜不到
- 想自定义组织弹幕库结构

## 弹幕库 · 导入 XML 弹幕文件

> 别名: 导入xml, 本地弹幕文件, 上传弹幕, 批量导入, dandanplay格式

支持导入 dandanplay 格式的 XML 弹幕文件。

**单文件导入**：条目详情页 → 点击 **导入 XML** → 选择 `.xml` 文件 → 自动解析导入。

**批量导入**：条目详情页 → 点击 **批量导入** → 选多个 `.xml` → 系统按文件名自动匹配分集 → 确认匹配结果后导入。

**XML 格式**：
```xml
<i>
  <d p="时间,类型,大小,颜色,时间戳,弹幕池,发送者,弹幕ID">弹幕内容</d>
</i>
```

## 拆分数据源（把分集移到新的源）

> 别名: 拆分源, 拆分数据源, 重整数据源, 分离源, 移动分集, 拆开源, 重整源, 拆分

**v2.5.1 起支持。** 把一个弹幕来源中的**部分分集移动到一个新建的数据源**里。

**操作步骤**：
1. 「弹幕库」选中目标条目 → 进入详情页
2. 在弹幕来源列表中选择要拆分的数据源
3. 点击 **拆分**
4. 勾选要拆出去的分集
5. 确认

**拆分结果**：被选中的分集移到新数据源（自动创建），原源剩余分集不变，**弹幕数据不会丢失**。

**为什么要拆分**：
- 一个源里混进了不同来源的弹幕，要分开管
- 同一源里部分集弹幕质量差，想单独管理
- 区分 TV 版 / BD 版
- 把质量好的分集拆出来单独设为默认来源

**想合并回去**：用「弹幕编辑」里的合并功能。

## 弹幕编辑（拆分 / 合并 / 时间偏移）

> 别名: 弹幕编辑, 拆分弹幕, 合并弹幕, 偏移弹幕, 时间轴, 弹幕不同步, 对不上, 时间差

**v2.5.0 起支持，要求弹幕源版本 ≥ 2.0.0。**

**入口**：「弹幕库」→ 选条目 → 进入分集详情页 → 点击 **弹幕编辑**。

| 功能 | 作用 |
|---|---|
| 拆分弹幕 | 把一集的弹幕按时间点切成多份 |
| 合并弹幕 | 把多集的弹幕并成一集 |
| 偏移弹幕 | 整体平移弹幕时间轴，解决弹幕与画面不同步 |

**拆分弹幕**：选分集 → 点 **拆分** → 设置拆分时间点（可多个）→ 预览 → 确认。
用于：合集视频的弹幕要按集分开、去掉片头片尾、长视频按章节切。

**合并弹幕**：选多个分集 → 点 **合并** → 设置合并顺序 → 预览 → 确认。
用于：上下集合成完整版、整合不同来源的同一集弹幕、合并分段视频弹幕。

**偏移弹幕**：选分集 → 点 **偏移** → 输入偏移时间（**正值延后，负值提前**）→ 预览 → 确认。
用于：弹幕与视频有固定时间差、不同版本片头时长不同。

⚠️ 弹幕编辑会**直接修改已存储的弹幕数据**，建议先备份。编辑后立即生效。

## 本地剧集组（集数映射 JSON）

> 别名: 剧集组, 集数映射, 集数对不上, 多季合并, OVA, SP, 特殊集

**v2.5.1 起支持。** 通过 JSON 文件手动定义"本地集数 → 弹幕源集数"的映射关系。

**解决什么问题**：
- 多季合并：媒体库把多季放一个文件夹连续编号（第二季从第 13 集开始）
- OVA / SP 等特殊集编号方式不同
- 不同平台对同一作品的分集方式不同（如合并放送）

**JSON 格式**：
```json
{
  "name": "作品名称",
  "groups": [
    { "season": 1, "episodes": [{"local": 1, "source": 1}, {"local": 2, "source": 2}] },
    { "season": 2, "episodes": [{"local": 13, "source": 1}, {"local": 14, "source": 2}] }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `name` | 作品名称，用于匹配 |
| `season` | 季数编号 |
| `local` | 本地文件的集数编号 |
| `source` | 弹幕源中对应的集数编号 |

**注意**：本地剧集组**优先级高于自动匹配**；JSON 格式要严格；改完需重新加载才生效。

## 首页搜索 · 编辑导入与「待导入 / 不导入」双列表

> 别名: 编辑导入, 不导入, 待导入, 排除分集, 删除分集按钮, 恢复分集, 区间过滤, 重整分集

在首页搜索到作品后，点 **编辑导入** 会打开分集编辑弹窗。弹窗里分集分成两个 Tab：

| Tab | 含义 |
|---|---|
| **待导入** | 会真正导入的分集。点某集的「删除」→ 该集移入「不导入」 |
| **不导入** | 被排除的分集。点「恢复」→ 移回「待导入」 |

**「不导入」里的分集从哪来**（每条会显示来源标签）：
- **源黑名单**：该弹幕源自己配的分集标题黑名单正则命中
- **全局过滤**：兜底全局分集标题过滤命中
- **单剧过滤**：该作品的专属过滤规则命中
- 用户手动删除的
- 区间过滤 / 重整过滤 / 库内已存在 批量排除的

**关键点**：被过滤的分集**不是丢弃，而是进「不导入」列表**，用户可手动恢复。
恢复后正常参与导入和弹幕下载。

**其他编辑能力**：改分集标题、改集号、拖拽排序、按集号区间批量排除、重整分集导入（换用另一个搜索结果的分集）。

## 首页搜索 · 补充源与集数偏移

> 别名: 补充源, 补充数据源, 集数偏移, 偏移预览, 识别词偏移

**补充源**：一个搜索结果可以额外挂一个其他平台的源，用于补齐缺失分集。

**集数偏移**：若配了识别词的 `partial_offset` 规则，编辑导入时会自动预览并应用集号偏移
（如源站「第 0 集」实际是「第 1 集」）。偏移后「待导入」和「不导入」列表的集号会同步调整。

## 弹幕源管理 · 资源仓库加载

> 别名: 弹幕源, 搜索源, 加载资源, 资源仓库, 装源, 更新源, 源版本

**入口**：Web UI 的 **搜索源** 页面 → **资源仓库** 卡片。

**配置步骤**：填入 GitHub 仓库链接或 CDN 加速链接 → 点 **保存** → 点 **加载资源**。

**官方仓库**：
- GitHub：`https://github.com/l429609201/Misaka-Scraper-Resources`
- Gitee：`https://gitee.com/l429609201/Misaka-Scraper-Resources`（需 ≥ v2.3.9，国内连通性更好，同步延迟约 5 分钟）
- CDN 加速：`https://cdn.jsdelivr.net/gh/l429609201/Misaka-Scraper-Resources`、
  `https://gh-proxy.org/https://github.com/...`、`https://proxy.pipers.cn/https://github.com/...` 等多个可选节点

**点「加载资源」会做**：自动备份当前源 → 下载最新源文件 → 安装 → 重载弹幕源。

**版本信息**：页面显示 **本地版本** 与 **远程版本**，有更新时提示「有更新」。

## 弹幕源管理 · 离线包上传 / 备份 / 重载

> 别名: 离线包, 上传源, 备份弹幕源, 还原备份, 重载弹幕源, 恢复源

**离线包上传**（无法在线加载时用）：
1. 到资源仓库 Releases 页下载对应平台架构的包（如 `linux-x86.zip`、`windows-amd64.zip`）
2. 「搜索源」页点 **离线包上传** → 选压缩包

**备份**：加载资源/上传离线包时会**自动备份**；也可手动点 **备份当前弹幕源**。
备份内容含所有 `.so`/`.pyd` 文件、`package.json`、`versions.json`。

**恢复**：点 **从备份还原** → 恢复所有文件与版本清单 → 重载。

**重载弹幕源**：改了源文件、更新了配置、或系统提示需重载时，点 **重载弹幕源**。

**故障排除**：
- 上传失败 → 检查格式是否 `.zip`/`.tar.gz`、包内是否含 `versions.json`、平台架构是否匹配
- 加载失败 → 检查仓库链接、网络能否访问 GitHub、换其他 CDN 节点、看系统日志
- 重载失败 → 检查文件是否完整、权限是否正确，可先从备份恢复再重载

## 订阅管理 · 追番订阅与追番日历

> 别名: 订阅, 追番, 追更, 日历, 追番日历, 批量订阅, 退订, 取消订阅

**v2.8.0 起提供**，入口是 Web UI 的 **订阅** 页面。页面分两部分：顶部统一搜索区 + 追番日历。

**关键词搜索订阅**：选「全部源」或指定源 → 输入作品名 → **搜索** →
系统同时用 bangumi-data 离线索引与在线源查找 → 核对后点候选项右侧 **订阅**。
- 「离线命中」= 候选来自本地 bangumi-data 索引
- 绿色平台标签 = 该平台有可抓弹幕的源

**URL 解析订阅**：粘贴视频/合集 URL → 点 **解析** → 可选「订阅当前视频」/「订阅整个合集」/「勾选部分视频批量订阅」。主要场景是 B 站视频与合集。

**追番日历**：按星期展示本地作品与外部日历项，无明确播出日期的进「其他作品」区。
工具栏支持：按名搜索、显示全部/本地/指定外部源、同步追番日程、清理日历缓存、查看各源项目数量。

**单项订阅**：点卡片 **订阅** → 确认媒体类型/季度/数据源 →
勾选 **立即执行** 则马上提交搜索导入任务；不勾选则只保存订阅，等后续扫描。

**批量订阅**：多选卡片（可按当天或当前过滤结果全选）→ 悬浮操作条点 **批量订阅** → 确认是否立即执行。

**取消订阅**：点已订阅卡片上的 **已订阅**。
多个外部源时需选择要解除哪个来源。**取消订阅不会删除已导入的作品/分集/弹幕。**

**v2.8.2 新增**：AniBT 元数据与私有 RSS 订阅（需先配好地址/凭据/授权）。
⚠️ 私有 RSS 地址含访问凭据，截图和反馈时必须遮盖。

**订阅页显示「暂无可用订阅源」时排查**：源是否已加载并启用 → 源是否支持订阅能力 →
OAuth/Cookie/私有 RSS 授权是否完成 → 服务端与源包版本是否兼容。

## 媒体获取（从 Emby/Jellyfin/Plex 读取 / 本地扫描）

> 别名: 媒体获取, 读取媒体库, emby, jellyfin, plex, 本地扫描, 扫描弹幕, 扫描目录

「媒体获取」页面提供三种获取媒体条目的方式：

| 方式 | 说明 | 适用场景 |
|---|---|---|
| 媒体服务读取 | 从 Emby/Jellyfin/Plex 获取 | 已有媒体服务器 |
| 本地扫描 | 扫描本地目录获取 | 无媒体服务器 |
| 扫描本地弹幕 | 扫描本地 `.xml` 弹幕文件 | 已有弹幕文件 |

**媒体服务读取**：
1. 「设置」→「媒体服务」→ 选类型 → 填服务器地址（如 `http://192.168.1.100:8096`）+ API Key
2. 点 **测试连接** 验证 → 保存
3. 「媒体获取」页点 **读取媒体库** → 选需要导入弹幕的条目

API Key 获取位置：Emby = 设置→高级→API 密钥；Jellyfin = 仪表盘→API 密钥；Plex = 设置→账户→Plex Token。

**本地扫描**：「设置」→「本地扫描」加扫描目录、配递归扫描与文件类型 → 「媒体获取」页点 **本地扫描**。
推荐标准目录结构：`剧集名/Season 01/S01E01.mkv`。

**扫描本地弹幕**：同样先在「本地扫描」配目录 → 「媒体获取」页点 **扫描弹幕** → 自动解析 `.xml` 导入。
XML 命名建议：电影 `电影名 (年份).xml`；剧集 `剧集名 S01E01.xml` 或 `剧集名 - 01.xml`。

## 弹幕 API · Token 管理

> 别名: token, 令牌, api密钥, 创建token, token日志, 调用限制

**入口**：**弹幕** → **Token 管理**。用于控制第三方应用（播放器）对弹幕 API 的访问。

**创建 Token**：点 **创建Token** → 填 Token 名称（如"我的播放器"）、有效期（30天/90天/永久）、
每日调用限制（可选）→ 确认。系统生成 20 位随机字符串。

**Token 管理能力**：查看列表与状态、一键复制 Token、删除、查看调用次数与有效期。

**Token 访问日志**（v2.7.2 增强）：记录请求方法、路径、请求体、响应体、状态码、来源 IP、调用时间。
通过 MCP Server 发起的调用带 `MCP:` 前缀，便于区分。

**典型用法**：为不同播放器分配独立 Token；给第三方应用授权；限制单 Token 调用频率。

## 弹幕 API · 播放器搜索框指令（@指令）

> 别名: 指令, @指令, QLHC, SXDM, CXLK, CXRW, 清理缓存指令, 刷新弹幕指令

⚠️ **指令仅在 anime 接口中支持**，需播放器支持该接口。所有指令**大小写均可**（`@qlhc` = `@QLHC`）。

在播放器的搜索框里输入指令并执行：

| 指令 | 作用 |
|---|---|
| `@` | 获取可用指令列表 |
| `@QLHC` | 清理缓存 |
| `@SXDM` | 刷新最近播放过的某集弹幕 |
| `@CXLK` | 查询流控状态 |
| `@CXRW` | 查询任务状态（可按状态和队列筛选） |

**`@SXDM` 三步交互**：
1. 输 `@SXDM` → 列出最近播放的番剧（最多 5 部），分配标签 `#A`~`#E`
2. 输 `@SXDM #A` → 看标签 A 番剧的分集列表（含缓存状态与弹幕数量）
3. 输 `@SXDM #A1` → 刷新标签 A 番剧第 1 集，提交刷新任务

**`@CXRW` 参数格式**：`@CXRW [状态#] [#队列] [状态#队列]`

状态标识（放 `#` 前）：`a#`全部 / `r#`进行中 / `c#`已完成 / `f#`失败 / `p#`排队中 / `s#`已暂停
队列标识（放 `#` 后）：`#d`下载队列 / `#m`管理队列 / `#b`后备队列

示例：`@cxrw r#` 查进行中；`@CXRW #d` 查下载队列；`@cxrw r#d` 查下载队列中进行中的任务。

## 弹幕 API · 弹幕输出控制（上限 / 随机颜色 / 输出黑名单）

> 别名: 弹幕输出上限, 弹幕太多, 卡顿, 随机弹幕颜色, 弹幕输出黑名单, 过滤广告弹幕, 屏蔽弹幕

**弹幕输出上限**：设置 API 返回的弹幕最大数量。
- `-1` = 无限制；正整数 = 限制数量（建议 3000~5000）
- 超限时系统**按时间段均匀采样**，保证弹幕在整个视频时长内分布均匀，避免客户端卡顿
- 推荐：移动设备 3000 / 桌面 5000 / 高性能 8000+

**随机弹幕颜色**：开启后为**原本没有颜色信息**的弹幕随机分配颜色；已有颜色的保持不变。

**弹幕输出黑名单**：过滤不想显示的弹幕内容。支持关键词与正则表达式。
**v2.7.0 起有「填充默认配置」按钮**，可一键写入推荐黑名单规则，再按习惯微调。
用于过滤广告、剧透、不文明用语、特定格式弹幕。

## 弹幕 API · 高级设置（匹配后备 / 后备搜索 / 顺延 / 预下载）

> 别名: 匹配后备, 后备搜索, 顺延机制, 预下载, 自动导入, match接口, 灰色不能点

这四个开关决定"播放器请求弹幕时，本地没有该怎么办"。

**匹配后备**：播放器走 `/match` 接口时，本地没有匹配弹幕 → **自动从弹幕源搜索并导入**。
流程：播放器发 `/match`（含文件名、Hash）→ 查本地 → 没有则自动搜索 → 找到后导入并返回。

**后备搜索**：播放器走 `/search/anime` 接口时，本地没结果 → **自动从弹幕源搜索并返回结果**供用户选择。

**两者区别**：匹配后备是 `/match` 触发、自动匹配导入；后备搜索是 `/search/anime` 触发、返回候选让用户选。

**顺延机制**：选中的源没有有效分集时（如只有预告片全被过滤掉），**自动尝试下一个候选源**，提高导入成功率。

**预下载**：播放当前集时，**后台自动下载下一集的弹幕**（若下一集存在且无弹幕）。
异步后台任务，不阻塞当前播放，不影响性能。

⚠️ **顺延机制和预下载依赖「匹配后备」或「后备搜索」**。
两者都没开时，这两个选项会被**禁用（灰色不可点）**——这是用户常问"为什么点不了"的原因。

**匹配后备 Token 授权**：为匹配后备配专用 API Token（可加多个自动轮换），提高调用限额、避免限流。

**匹配后备黑名单**：阻止特定作品或特定源被自动导入。
用于：某作品弹幕质量差不想自动导；某源经常匹配错要屏蔽。

## 设置 · 安全设置（IP白名单 / 受信任反代 / 登录锁定）

> 别名: 安全设置, IP白名单, 受信任反代, 反向代理, 真实IP, 登录锁定, 登录失败, 429, 进不去, 打不开

**入口**：**设置** → **参数配置** → **安全设置**。

**GitHub Token**：用于访问 GitHub API 检查弹幕源更新。
配置后限额从 60次/小时 提升到 5000次/小时。到 github.com/settings/tokens 生成，勾 `public_repo` 权限。

**访问 IP 白名单**：开启后只有白名单 IP 能访问。支持单 IP（`192.168.1.100`）和 CIDR（`192.168.1.0/24`），每行一个。
⚠️ 配错会导致自己也无法访问，务必谨慎。

**受信任反代**：部署在 Nginx/Cloudflare 等反代后面时，系统收到的是代理 IP 而非用户真实 IP。
配置受信任反代后，系统会从 `X-Forwarded-For` / `X-Real-IP` 提取真实 IP。
**不配会导致**：所有用户被识别为同一个反代 IP、IP 白名单判断不准、一人输错密码锁定影响所有人。

**登录失败锁定**（v2.7.5 起）：同一真实 IP 连续登录失败达上限后临时锁定。

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `loginMaxFailCount` | `3` | 失败次数上限，设 `0` 禁用防护 |
| `loginLockoutMinutes` | `60` | 锁定时长（分钟） |

被锁定时登录接口返回 429，前端提示「登录失败次数过多，请稍后再试」。

**管理员自己被锁定的解法**（需服务正在运行）：
```bash
python -m src.reset_login_lockout --clear
python -m src.reset_login_lockout --clear --ip 192.168.1.100
```
服务已停止时，**直接重启服务即可清空**锁定记录（记录在内存中）。

**三种机制的区别**（排查"访问不了/登不上"时先区分）：

| 机制 | 作用 | 典型问题 |
|---|---|---|
| IP 白名单 | 允许谁访问 | 当前 IP 未加白名单 |
| 受信任反代 | 是否从 HTTP 头识别真实 IP | 反代配错，所有人被识别为反代 IP |
| 登录失败锁定 | 同一 IP 失败太多后禁止登录 | 密码输错多次被锁 |

## 设置 · MFA（TOTP 两步验证 / PassKey）

> 别名: 两步验证, TOTP, PassKey, MFA, 验证器丢了, 登不上, 重置MFA

Web UI 的 **安全设置** 里可以：启用/关闭 TOTP、注册/重命名/删除 PassKey。
**注册 PassKey 前必须先启用 TOTP**；关闭 TOTP 需输入当前密码确认。

**验证器丢失导致无法登录时**，用紧急重置工具：
```bash
python -m src.reset_mfa admin              # 清空 TOTP + 所有 PassKey
python -m src.reset_mfa admin --totp       # 仅重置 TOTP
python -m src.reset_mfa admin --passkey    # 仅重置 PassKey
```
Docker：`docker exec -it misaka_danmu_server python -m src.reset_mfa admin`

重置后可仅用密码登录，登录后建议重新绑定。
**v2.7.5 增强**：TOTP Secret 改为加密存储；PassKey challenge 改用随机 sessionId 避免并发覆盖。

## 设置 · 名称转换（繁简转换 / 自定义映射）

> 别名: 名称转换, 繁体转简体, 繁简, 搜不到, 名字对不上, 自定义转换

**v2.4.3 起支持，繁体转简体自 v2.5.2 起支持。**
**入口**：**设置** → **参数配置** → **名称转换**。

## 常见困惑速查（回答时优先核对这里）

> 别名: 常见问题, FAQ, 为什么, 怎么办, 不生效, 没反应

| 用户说法 | 真正指向的功能 | 关键答案 |
|---|---|---|
| "删了之后分集不见了" | 编辑导入的「不导入」列表 | 删除是移入「不导入」，可点恢复移回，不是真删 |

| "弹幕和画面差几秒" | 弹幕编辑 → 偏移 | 正值延后、负值提前 |
| "集数对不上" | 本地剧集组 / 识别词集数偏移 | 剧集组做 local→source 映射；识别词做整体偏移 |

| "突然登不上了" | IP白名单 / 反代 / 登录锁定 | 先区分三种机制，看是 403 还是 429 |
| "改了源配置没生效" | 重载弹幕源 | 「搜索源」页点「重载弹幕源」 |
