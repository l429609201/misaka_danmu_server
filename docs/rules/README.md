## 🎯 Agent 执行规则

### 任务前检查 (Pre-Flight Check)

在生成代码或提出修改前，必须：

1. **识别涉及的领域**（任务系统？数据源？数据库？）
2. **加载对应的规则文档**（不是"建议"，是"必须"）
3. **使用工具验证**（`view`、`codebase-retrieval`）
4. **直接实施修改**（不是"建议用户做"）

### 强制执行模式

**禁止的响应模式**：
- ❌ "你需要检查 X 文件"
- ❌ "可能是 Y 有问题"
- ❌ "建议查看 Z"

**必须的响应模式**：
- ✅ `[view X]` → 分析 → 报告发现
- ✅ `[codebase-retrieval Y]` → 定位 → 修复
- ✅ `[str-replace-editor Z]` → 验证 → 报告完成

### 最小化修改原则

- 优先最小、正确的修改
- 不做无关重构
- 不批量重命名
- 不格式化无关代码

## 🔗 耦合更新规则

修改以下内容时，必须同时更新：

| 修改内容 | 必须更新 |
|---------|---------|
| 数据库模型 | 创建 Alembic migration |
| 数据源配置字段 | `configurable_fields` + 版本号 |
| 任务系统接口 | `TaskManager` 相关测试 |
| API 接口 | 对应的前端代码 |
| 通知事件 | `notification_scopes` API |
