# 御坂技能编写指南

技能（Skill）是给御坂助手看的**场景化作业指导书**。当你的需求匹配某个技能的触发条件时，御坂会先读取该技能的正文，再按其中的步骤执行，而不是凭通用知识临场判断。

## 为什么需要技能

御坂的 system prompt 里已经写明了所有工具的用途，但有些任务需要**特定顺序的多步操作**，且步骤间有依赖和陷阱。例如导入综艺，必须先配好单剧过滤规则再拉分集列表，否则会把「加更」「纯享」版本一起导进来。这类流程知识写进技能，比每次对话都重新解释更可靠。

## 存放位置

```
config/skills/
├── import-variety-batch/
│   └── SKILL.md
├── diagnose-danmaku-missing/
│   └── SKILL.md
└── 你的技能ID/
    └── SKILL.md
```

Docker 部署时路径为 `/app/config/skills/`。目录名即技能 ID，必须是**小写字母、数字、短横线**的组合。

## 文件格式

`SKILL.md` 由 YAML frontmatter（元数据）和 Markdown 正文（指导书）两部分组成：

```markdown
---
name: 批量导入综艺
version: 1
description: 用户要批量导入综艺（尤其需要配合单剧过滤规则过滤加更/纯享/预告版本）时使用此技能。
allowed-tools: search_media get_provider_episodes import_edited set_single_episode_filter
enabled: true
---

## 触发时机
- 用户说"导入xxx综艺"、"帮我把xx的所有集都导进来"

## 工作流程
1. **搜索媒体**：调用 `search_media` 找到该综艺
2. **检查过滤规则**：调用 `get_single_episode_filter` 看是否已有规则
3. **获取分集**：调用 `get_provider_episodes`
4. **确认后导入**：调用 `import_edited`

## 关键注意
- 综艺常有重复版本，单剧过滤是关键环节，不能跳过
```

## 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | 是 | 技能中文名，展示用 |
| `version` | 否 | 版本号，默认 1。前端编辑时自动递增 |
| `description` | 是 | **触发时机描述**，这是最关键的字段（见下文） |
| `allowed-tools` | 否 | 推荐工具列表，空格分隔。仅作提示，不做技术拦截 |
| `enabled` | 否 | 是否启用，默认 `true`。停用后不再注入 system prompt |

### description 为什么最关键

御坂的 system prompt 里**只有**技能的 ID、名称和 `description`，没有正文。它靠 `description` 判断"这个需求是否该读这份指导书"。所以：

写得好：`用户要批量导入综艺（尤其需要配合单剧过滤规则过滤加更/纯享/预告版本）时使用此技能。`
写得差：`导入综艺用的。`

前者说清了场景和适用条件，后者太笼统，容易漏触发或误触发。

这个设计叫**渐进式披露**：摘要常驻 prompt，正文按需加载，这样技能数量增长也不会撑爆上下文。

## 正文写法

正文是给 LLM 看的操作手册，建议三段结构：

**触发时机**：列举用户可能的原话，帮御坂对齐语义。

**工作流程**：编号步骤，每步写明调用哪个工具、传什么参数、拿到什么结果。工具名用反引号标注，御坂识别度更高。

**关键注意**：写陷阱和约束。比如"写入前必须先测试正则"、"mode 务必用 append 不要 replace"、"绝不跳过用户选择直接导入"。这部分最能体现技能价值 —— 通用 prompt 里塞不下这么细的约束。

## 三种创建方式

**前端 UI**（推荐）：设置 → AI → 御坂技能 → 新建技能。编辑器带模板提示，保存即生效。

**手动放文件**：按上述格式写好 `SKILL.md` 丢进目录，然后在前端点「重载目录」，或调 `POST /api/ui/assistant/skills/reload`。不需要重启服务。

**让御坂自己写**：直接说「把刚才这个流程记下来做成技能」，御坂会调 `create_skill` 工具，弹确认卡给你过目后落盘。

## 内置示例

系统预置了三个技能，可以直接打开看写法：

- `import-variety-batch` — 批量导入综艺，演示多工具串联与前置检查
- `diagnose-danmaku-missing` — 诊断弹幕缺失，演示按三层过滤链逐层排查的诊断路径
- `configure-recognition-rules` — 配置识别词，演示"先测试再写入"的安全流程

这些文件在首次启动时写入，之后**不会被覆盖**，你可以放心修改。如果想恢复原版，删掉目录重启即可。

## 常见问题

**改了文件没生效？** 点「重载目录」，或确认 YAML frontmatter 的 `---` 分隔符前后没有多余空格。

**技能没被触发？** 检查 `description` 是否说清了场景，以及 `enabled` 是否为 `true`。也可以直接问御坂「你有哪些技能」，它会调 `list_skills` 列出来。

**allowed-tools 写错了会怎样？** 不会报错。它只是提示信息，御坂实际能调用的工具由全局注册表决定，不受此字段限制。
